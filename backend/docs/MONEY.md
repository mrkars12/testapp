# معيار التعامل مع الفلوس

هذا المستند ملزم. أي كود جديد يتعامل مع مبالغ مالية يجب أن يتبعه.

## القواعد

### 1. الفلوس = عدد صحيح بالوحدات الصغرى + رمز عملة

```ts
// ✅ صح
const price: Money = money(1050n, 'USD')   // 10.50 دولار

// ❌ غلط
const price = 10.50
const price = new Decimal('10.50')
```

`Decimal` مسموح فقط في أعمدة التسعير القديمة الموجودة حالياً، لحين
مراجعتها في المرحلة 1b. ممنوع تماماً في أي شيء يخص الدفع أو الدفتر.

### 2. ممنوع `parseFloat` أو `Number` على مبلغ نصي

التحويل الوحيد المسموح به يتم عبر `parseDecimal` في
`src/common/money/money.util.ts`. هذه هي النقطة الوحيدة التي يدخل منها
مدخل خارجي إلى نظام الفلوس، والتحقق فيها صارم.

`WalletModule` هو الاستثناء الوحيد المسموح به، وهو استثناء قديم مغلق
أمام أي استخدام جديد.

### 3. الأرصدة تُشتق من قيود غير قابلة للتعديل

```ts
// ❌ غلط
await prisma.wallets.updateMany({ data: { balance: { increment: x } } })

// ✅ صح
// قيد جديد في الدفتر، والرصيد يُحسب من مجموع القيود
```

### 4. كل صف يحمل مبلغاً يحمل `store_id` و `mode` و `currency`

بدون استثناء.

### 5. العمليات الحسابية بين نفس العملة فقط

`add` و `subtract` و `compare` ترمي `CurrencyMismatchError` عند اختلاف
العملة. التحويل بين العملات عملية صريحة تُسجَّل في الدفتر، وليست
تحويلاً ضمنياً في عمود.

### 6. تحويل الأس لصيغة البوابة مسؤولية الأدابتر

الأس يُقرأ من `currency.registry.ts` فقط. ممنوع افتراض أن ×100 هو
التحويل الصحيح.

| الفئة | أمثلة | ملاحظة |
|---|---|---|
| أس 0 | JPY, KRW | لا خانات عشرية |
| أس 2 | USD, EGP, SAR | الحالة الشائعة |
| أس 3 | KWD, BHD, OMR | `Decimal(12,2)` يفقد بيانات هنا |

## التقسيم بدون ضياع

`allocate` تستخدم خوارزمية أكبر باقي، وتضمن أن مجموع الأجزاء يساوي
المبلغ الأصلي بالضبط — مثبتة باختبار خصائص على آلاف الحالات.

```ts
allocate(money(100n, 'USD'), [1n, 1n, 1n])
// → [34, 33, 33]  المجموع = 100 بالضبط
```

المبالغ السالبة (عكس الاسترداد) تُعالج بالقيمة المطلقة ثم تُستعاد
الإشارة، لأن قسمة `bigint` تقرّب ناحية الصفر.

## حدود الاستخدام

- `toGatewayInteger` ترفض التحويل إذا تجاوز المبلغ المدى الآمن
  لـ `number` بدلاً من فقدان الدقة بصمت.
- خدمات التشفير (`EncryptionService` و `StoreKeyService`) مخصصة
  لبيانات تُكتب نادراً كالاعتمادات. لا تُستخدم لبيانات عالية الحجم:
  الـ IV العشوائي 96-bit يحدّ الاستخدام الآمن بحوالي 2^32 عملية
  لكل مفتاح.
